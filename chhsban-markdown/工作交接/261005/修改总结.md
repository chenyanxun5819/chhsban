## 🔗 系统间的数据流

### 额外加课流程

```
Super_admin 在 admin-portal
    ↓
点击"額外加課" → 选课程 → 选日期 → 输入备注 → 送出
    ↓
POST /api/schedule/extra (chhsban-tution)
    ├─ 验证权限、课程、日期有效性
    ├─ 检查日期占用
    ├─ 保存到 KV (extra status)
    └─ 返回 OK
    ↓
老师在 tution-portal
    ├─ 排课表自动包含新的 extra 日期
    └─ 点名系统可对 extra 日期进行点名

老师查看排课表 (scheduleGenerator)
    └─ 自动融入 extra 状态行，显示在原课程日期之后
```

### 维护通报流程

```
定时任务触发 (每日检查)
    ↓
判断是否需要执行数据清理 (retention.ts)
    ├─ 每年 12/1 检查前一年资料
    ├─ 分批标记为待清理
    └─ 生成维护通报记录
    ↓
Admin 在 admin-portal 查看
    ├─ 点击"系統維護通報"
    ├─ 看到清理进度和预计完成时间
    └─ 状态显示为"進行中"或"已完成"
```

## 🔍 重点设计决策

### 1. 额外加课作为正式状态而非独立数据

**决策**: 将 `extra` 加入 `ScheduleStatus` 枚举

**原因**:
- 自然整合到现有排课表、点名合法日期判断、出席统计
- 避免旁路逻辑（如单独表存储）
- 排课生成算法、统计报表等自动支持，无需特殊处理

### 2. 权限设置为 super_admin 专用

**决策**: 后端 API 返回 403 Forbidden 若非 super_admin

**原因**:
- 额外加课影响教室、师资分配
- 需要管理员级别的审核
- 老师无权单方加课

### 3. 日期占用检查

**决策**: 新增额外加课时，调用 `generateScheduleRows()` 检查该课程该周期内所有有课日期

**原因**:
- 确保不会重复加课（同一日期不能加两次）
- 复用现有的排课逻辑，减少代码重复

### 4. 维护通报与清理规则分离

**决策**: 规则逻辑在 `retention.ts` 中独立定义，通报页面仅展示和更新状态

**原因**:
- 便于单元测试清理规则
- 前端只关心展示和状态管理，后端处理业务逻辑
- 降低耦合

### API 验证流程

```typescript
// chhsban-tution/src/index.ts (简化版)
POST /api/schedule/extra {
  courseId: string,
  date: string,
  note: string
}

1. 检查 session.permission === "super_admin"
   → 否: 返回 403 Forbidden

2. 验证课程存在且未结束
   → 否: 返回 404 Not Found

3. 验证日期格式和范围
   → 否: 返回 400 Bad Request

4. 生成该课程的所有排课日期
   → 检查新日期是否已占用
   → 是: 返回 409 Conflict

5. 保存到 KV (status: "extra")
   → 成功: 返回 200 OK + id
```

### 排课生成支持 extra

```typescript
// tution-portal/src/utils/scheduleGenerator.ts (简化版)
function generateScheduleRows(course) {
  const rows = [];
  
  // 1. 生成原定课程日期
  for (const row of baseSchedules) {
    rows.push({
      date: row.date,
      status: row.status,  // scheduled, adjusted, cancelled
      // ...
    });
  }
  
  // 2. 追加额外加课日期
  for (const extra of course.extraSessions) {
    if (extra.status === "extra") {
      rows.push({
        date: extra.date,
        status: "extra",
        note: extra.note,
        // ...
      });
    }
  }
  
  // 3. 按日期排序
  rows.sort((a, b) => new Date(a.date) - new Date(b.date));
  return rows;
}
```
