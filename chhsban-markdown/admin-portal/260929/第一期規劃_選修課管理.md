# admin-portal 第一期規劃：建立管理站，先搬選修課管理

日期：2026-09-29
新專案位置：`D:\chhsban\admin-portal`
網址：`https://chhsban-admin.pages.dev`（Cloudflare Pages 專案名稱 `chhsban-admin`）

## 背景與目標

選修課的行政端原本在 2026-09-28 被整合進 `tution-portal`（`/optional/courses`），
但 tution-portal 的專案名稱與內容不符，時間一久會忘記選修課的東西放在補習班專案裡，難以追溯。

決定：**所有管理頁獨立成 `admin-portal`**，依專案名稱就能判斷東西在哪裡：

| 專案 | 內容 |
|---|---|
| `admin-portal` | 所有行政管理頁（補習班、選修課、共用設定） |
| `tution-portal` | 補習班老師端（網址不變，老師照常使用） |
| `optional-course` | 選修課老師端＋選修課 Worker |

分兩期：

- **第一期（本文件）**：建立 admin-portal，放入選修課管理（總覽、行事曆、點名追蹤）
- **第二期**：搬補習班管理（審批、已開課、報表、出席、教室使用）與共用設定（老師、密碼重設、教室），另立規劃

## admin-portal 資料夾結構

依「系統」分資料夾，一眼就知道每個檔案屬於哪個系統：

```
admin-portal/
  src/
    shared/          登入、權限、Layout（側邊欄）、共用樣式
    optional/        選修課管理（第一期）
      pages/         CourseList、Calendar、AttendanceTracking
      services/      呼叫 optional-course-system Worker
      utils/         行事曆判定（與 worker/src/calendar.ts 規則一致）
      optional.css   樣式一律 .oc- 前綴
    tution/          補習班管理（第二期）
  public/
    calendar-template.xlsx
```

## 登入與權限

- 登入流程沿用 tution-portal 的兩階段密碼登入，呼叫 `tution-system` Worker 的 `/api/auth/*`
  （與 optional-course-system 共用同一個 AUTH_KV，token 兩邊都認得）
- token 存在瀏覽器 localStorage，各網域獨立 → 管理員第一次進新站要登入一次（帳密不變）
- 只有 `super_admin`、`admin`（督察員）能進入；其他身分顯示「本站僅供行政人員使用」，並附老師端連結
- 權限與現行一致：super_admin 可修改；督察員只能查看

## 第一期頁面

| 路徑 | 頁面 | 說明 |
|---|---|---|
| `/optional/courses` | 選修課總覽 | 從 tution-portal 搬來（建課、綁老師、開關／重新開放、刪除），**新增上課星期設定**與點名統計 |
| `/optional/calendar` | 選修課行事曆 | 全年月曆、假期／補課日、Excel 匯入、影響檢查（已完成的 AdminCalendar 移入） |
| `/optional/attendance` | 選修課點名追蹤 | 依課程／依日期檢視未點名（已完成的 AdminAttendance 移入） |
| `/optional/courses/:id/schedule` | 課程停課／調課 | super_admin 登記，督察員唯讀 |

側邊欄三組：

- **補習班**：第一期先以外部連結指向 tution-portal 原本的管理頁（標示 ↗），第二期搬進來後改為站內連結
- **選修課**：上述三頁
- **共用設定**：同補習班，第一期先連到 tution-portal

## 部署

1. 建立 Cloudflare Pages 專案 `chhsban-admin`（一次性）
2. 新增 `.github/workflows/deploy-admin-portal.yml`（比照 deploy-optional-course.yml，paths: `admin-portal/**`）
3. push 後三個前端各自由 GitHub Actions 部署：admin-portal、tution-portal、optional-course
4. 順序：admin-portal 先上線確認可用 → 再上 tution-portal 的轉址（避免轉址到還不存在的頁面）
