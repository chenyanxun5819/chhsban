## 详细变更

### 1️⃣ Firestore `jobs/{jobId}` 数据模型

**新增字段**: `answerKey`

```diff
jobs/{jobId}: { 
  "uid": "...", 
  "orgId": "...", 
  "templateId": "...", 
  "status": "...", 
+ "answerKey": ["A","C","B",...],        // 标准答案数组
  "result": {…精简结果 JSON…}, 
  "pages": 1, 
  "createdAt": ..., 
  "expiresAt": ...
}
```

**作用**: 存储该次考试的标准答案，在识别时用于自动对比学生答案。

---

### 2️⃣ 第 3.3 节（预留功能）新增说明

**内容**: 明确 M7 中标准答案的获取方式及与试卷库的关系

**新增行**：
> **标准答案**（M7 实作）：每次考试的 `answerKey` 是一个数组，长度 = 题数，每项为 A/B/C/D/E。存入 Firestore `jobs/{jobId}` 并在识别时用于对比。来源可为：① 扫描标准答案卡（图片）后自动识别、或 ② 手动输入。标准答案本次考试内有效；考试结束可修改或删除。第一阶段暂不进试卷库（永久保存的试卷库属第二阶段，见 14.3 节）。

**意义**: 澄清标准答案在 M7 的角色，避免与第二阶段试卷库混淆。

### 3️⃣ M7 教师端流程（完全重写）

**原版（缺陷）**:
```
① 选择版型、填考试名/科目 → 下载答案纸 PDF
② 上传扫描 → 识别 → 结果表
③ 下载结果 CSV 与标注图 PDF
```
**问题**: 没有标准答案输入步骤，导致识别后无法对比。

**新版（完整）**:
```
① 新建考试与获取标准答案（新增）
   ├─ 方案 A：扫描标准答案卡
   │  - 上传卡片图片
   │  - 系统自动识别
   │  - 预览 + 手动调整
   └─ 方案 B：手动输入答案
      - 逐题或粘贴 JSON/CSV

② 学生答卷扫描与识别（修改）
   - 自动与标准答案对比
   - 生成答对/答错/未作答判定

③ 查看与导出结果
   - 结果表（含对错状态）
   - 标注图 PDF
   - CSV 导出
```

**新增验收标准**:
- 方案 A：标准答案卡识别准确率 = 100%
- 方案 B：手动输入支持 JSON/CSV 导入导出
- 对比逻辑：答对/答错/未作答判定正确
- 数据持久化：answerKey 正确存储 24 小时后删除

## 实现建议

### 前后端分工

| 模块 | 说明 |
|------|------|
| **前端**（HTML + Firebase JS） | 标准答案输入UI（两种方式）、对比结果展示 |
| **后端**（Cloud Functions） | 标准答案卡识别、学生答卷识别、对比逻辑 |
| **核心库**（omr_core） | 无需修改（标准答案卡用同一套识别） |

### 新增 Cloud Functions

1. `upsertAnswerKey(jobId, answerKey)` 或 `uploadAnswerKeySheet(...)`
   - 接收标准答案（手动输入或扫描卡片识别结果）
   - 验证格式（长度、字符范围）
   - 存入 `jobs/{jobId}.answerKey`

2. 修改现有 `recognize_sheet(jobId, storagePath, templateId)`
   - 识别学生答卷后，自动读取 `jobs/{jobId}.answerKey`
   - 对比并生成 `correctness` 数组
   - 返回对比结果

### 测试覆盖

- 单元测试：answerKey 格式验证
- 集成测试：标准答案卡扫描识别（E2 实验）
- 端到端测试：完整工作流（上传卡 → 下载答案纸 → 上传学生卷 → 查看对比结果）

## 备注

- 标准答案的**修改权限**：教师可在识别前修改，识别后不可修改（防止事后改答）
- 标准答案的**删除**：随整个 `jobs/{jobId}` 文档在 24 小时后自动删除
- 标准答案**不计费**：识别卡片不计入教师的日识别张数配额（仅学生答卷计费）
- 标准答案**不保存截图**：不在 Cloud Storage 中留下中间文件（仅在 Firestore 存 JSON）
