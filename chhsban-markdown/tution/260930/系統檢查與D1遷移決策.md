## 二、檢查發現（依嚴重度）

### 🔴 致命：幾週內會壞

**1. tution 出勤超過 1000 筆後會「消失」／點名頁 500**
- `tution-service.ts` 的 `listAttendanceByClass` 用 `list({prefix:"attendance_"})` 不帶 cursor，再逐筆 GET 全系統出勤後才過濾。
- 出勤是「每位學生每次點名一個 key」，以 9 班 × 約 22 人 × 每週一次，**約 11 月初超過 1000 筆**。
- 後果：KV list 只回最舊的 1000 筆 → 老師剛存的點名看不到 → 反覆重存燒 PUT；單次請求超過 1000 次 KV 操作上限 → 500；在那之前，每開一次點名頁就讀全系統出勤，可能耗光全帳號每日讀取額度，所有系統（含登入）當天停擺。
- 同樣沒翻頁＋全表掃描的：`listRosterByClass`、`listSchedulesByClass`、`listClassesByTeacher`、`listAllClasses`（名單 196 筆，較不急）。
- **決定：改用 D1 解決（見第四節）。**

### 🔴 安全漏洞（與資料庫無關，搬 D1 也要補）

**2. 只要知道 email 就能搶先設定密碼並登入**
- 帳號尚未設密碼時，`/api/auth/verify` 只憑 email 就發 `password_setup` token。
- 前端 Google 登入只在瀏覽器解 JWT 取 email（`tution-portal/src/pages/Login/Login.tsx:55`），後端沒驗證 Google 簽章。
- 管理員「重設密碼」後會重新打開這個窗口；admin（督察員）也能重設 super_admin 密碼。
- 修法：後端驗證 Google ID token 並限定學校網域（`hd` 欄位），可結合 Workspace；重設密碼限 super_admin 且不能重設同級以上。
- **馬上可做**：在 admin-portal 教師列表確認所有 admin／super_admin 的 hasPassword 都是 ✓。

**3. 老師可以自己把課程改成「已批准」**
- `PUT /api/v1/classes/{id}` 整包合併 body，無欄位白名單，可送 `approval_status`、`receipt_h1.status`、`teacher_id`、`venue`。
- `POST /classes` 可夾帶 `receipt_h1`；`PUT /schedules/{id}` 可改 `class_id`。
- 修法：白名單。老師只能改 `end_date`（待審階段再加申請表欄位）。

**4. 任何登入者都能看任何老師的課程與學生名單**
- `GET /api/v1/classes?teacher=X` 沒檢查 X 是否本人。

**5. `/api/sync` 問題**
- `?action=init&key=init` 免登入即可觸發 Google Sheets 初始化（寫死的後門）。
- `sync-all` 任何老師都能觸發全表讀取。前端沒用到，建議刪除或限 super_admin。

**6. Google Sheets API Key 明文進了 git**
- `chhsban-tution/wrangler.toml` 第 129 行註解，以及 chhsban-markdown 約 6 份文件。repo 若公開須到 Google Cloud 輪換。

### 🟠 Cloudflare 額度浪費

7. **登入輸入未註冊 email 會全表掃描教師**（兩個 Worker 都是，1 list + 143 GET，免登入即可觸發；也可用來探測 email 是否註冊）。修法：一次建好所有 email 索引，拿掉 fallback 掃描。
8. **tution 每次名單／班級寫入都同步 Google Sheets 並等待完成**：讀全部班級＋全部名單（約 210 次讀，隨學期累積）再清空重寫。沒人看就拿掉，要保留就改每日 cron。
9. **tution 點名每存一次是「學生數 + 1」次 PUT**（免費版全帳號每天 1000 次）。搬 D1 後解決。

### 🟡 閉環缺口

10. 刪除班級只刪班級與名單，出勤、排課例外、R2 收據／簽核檔成為孤兒資料；且老師可刪已批准、已點名的課。
11. tution 沒有資料保留／清理機制（optional-course 有保留 3 年的 cron）。
12. 申請編號用「今年建立數 + 1」，刪過申請就會撞號（optional-course 已改用計數器）。
13. 點名缺少檢查：學生是否在名單、是否未來日期；optional-course 未檢查 status 值、退出日期晚於加入日期、`max_students` 上限。
14. 有 3 個檔案未 commit（`tution-service.ts`、`course-report.ts`、`index.ts`，出勤統計 `stats:` 功能），尚未部署。**搬 D1 後統計可直接用 SQL `GROUP BY` 算，這組功能可能不再需要，動工前先決定保留或捨棄。**
15. `/classes/:id/stats` 是壞頁（呼叫不存在的 `/api/v1/rosters`，且路徑變 `/api/api`）；`useRoster`、`useClasses`、`googleSheetsSync.ts` 是死代碼。

## 三、資料庫方向討論與決定

### 考慮過的方案

| 方案 | 結論 |
|---|---|
| 搬 Firestore | **不採用**。Workspace 不包含 Firestore，額度與計費另計；不綁卡只能從 Worker 打 REST（要自簽 JWT、每次請求外部呼叫上限 50），要順暢得連後端搬到 Cloud Functions（需綁卡的 Blaze 方案）。5 個 Worker 共用 AUTH／TEACHER／STUDENT KV，等於全部重寫，估 4～8 週。 |
| 付費 Workers（US$5/月）+ 改 key 設計 | **不採用**。需要綁信用卡，使用者不付費。 |
| **Cloudflare D1（SQLite）** | **採用**。免費版可用、不需綁卡；同帳號、Worker 原生綁定、可用 SQL 查詢。 |

### D1 免費版限制（以 Cloudflare Dashboard 顯示為準）

- 每天讀 500 萬行、寫 10 萬行，UTC 00:00（馬來西亞早上 8 點）重置。
- 每個資料庫最大 500 MB，最多 10 個資料庫。
- 超額只會讓當天查詢失敗，不會扣款。
- **注意**：「讀取行數」是 SQL 掃描過的行數，不是回傳行數。常查的欄位（`class_id`、`class_date`、`student_id`）一定要建索引，否則每次都掃全表。

### Workspace 的角色

Workspace 真正有用的是**登入**（後端驗證 Google 帳號、限定學校網域，同時修掉漏洞 #2）與**報表匯出到 Sheets**，兩者都不需要搬資料庫。

## 四、D1 遷移計畫

### 範圍（第一階段）

原計畫只搬出勤與名單；實作時**班級、排課例外、系統設定也一併搬進 D1**（資料量小，且能讓刪除清理、保留年限、編號計數器直接用 SQL 做）。登入、教師、學生名錄、教室仍留在 KV，不動其他 Worker。

### 資料表設計草案

```sql
-- migrations/0001_init.sql

CREATE TABLE tution_roster (
  roster_id          TEXT PRIMARY KEY,
  class_id           TEXT NOT NULL,
  student_id         TEXT NOT NULL,   -- SMS 內部編號
  student_no         TEXT,            -- 學號
  student_name_cn    TEXT,
  student_name_en    TEXT,
  student_class      TEXT,
  gender_boarding    TEXT,
  enrollment_date    TEXT,            -- YYYY-MM-DD
  withdrawal_date    TEXT,
  withdrawal_reason  TEXT,
  is_active          INTEGER NOT NULL DEFAULT 1,
  created_at         INTEGER NOT NULL,
  updated_at         INTEGER NOT NULL
);
CREATE INDEX idx_roster_class   ON tution_roster(class_id);
CREATE INDEX idx_roster_student ON tution_roster(student_id);
CREATE INDEX idx_roster_no      ON tution_roster(student_no);

-- 保留「新增制」完整歷史
CREATE TABLE tution_attendance_log (
  attendance_id   TEXT PRIMARY KEY,
  class_id        TEXT NOT NULL,
  student_id      TEXT NOT NULL,
  class_date      TEXT NOT NULL,
  status          TEXT NOT NULL,      -- present / absent / late / excuse
  absence_reason  TEXT,
  recorded_at     INTEGER NOT NULL,
  recorded_by     TEXT
);
CREATE INDEX idx_att_log_class_date ON tution_attendance_log(class_id, class_date);

-- 每位學生每堂課的「目前狀態」，查詢一律讀這張
CREATE TABLE tution_attendance (
  class_id        TEXT NOT NULL,
  student_id      TEXT NOT NULL,
  class_date      TEXT NOT NULL,
  status          TEXT NOT NULL,
  absence_reason  TEXT,
  recorded_at     INTEGER NOT NULL,
  recorded_by     TEXT,
  PRIMARY KEY (class_id, student_id, class_date)
);
CREATE INDEX idx_att_date    ON tution_attendance(class_date);
CREATE INDEX idx_att_student ON tution_attendance(student_id);
```

點名儲存時，同一個 `batch()` 內對每位學生：INSERT 一筆到 `tution_attendance_log`，並 `INSERT ... ON CONFLICT(class_id, student_id, class_date) DO UPDATE` 到 `tution_attendance`。原本的 `dedupeToLatestAttendance` 與 `stats:` 統計都可由 SQL 取代。

### 執行步驟

1. **建立資料庫**：`npx wrangler d1 create tution-db`，把輸出的 `[[d1_databases]]`（binding 建議 `DB`）加進 `chhsban-tution/wrangler.toml` 預設區段。
2. **建表**：`npx wrangler d1 migrations apply tution-db --remote`（先 `--local` 測）。
3. **改寫 `TutionKVService`**：`addRosterEntry`、`getRosterEntry`、`updateRosterEntry`、`deleteRosterEntry`、`listRosterByClass`、`listAllRoster`、`recordAttendance`（改為整批）、`listAttendanceByClass`、`listAttendanceByStudent`、`listAllAttendanceSummaries`、出勤統計相關函式。`index.ts` 的呼叫端盡量不改，API 回傳格式維持不變，前端就不用動。
4. **一次性搬資料**：寫腳本把 KV 的 roster（約 196 筆）與 attendance（約 131 筆）讀出、轉成 SQL INSERT，用 `npx wrangler d1 execute tution-db --remote --file=...` 匯入。出勤匯入時同時寫 log 表與 current 表（current 取每組最新一筆）。
5. **部署**：選晚上 21:00 補習課結束後，順序為「匯入資料 → 部署 Worker → 開點名頁／名單頁驗證」。
   - ⚠️ 一律用**不帶 `--env`** 的 `npx wrangler deploy`，`--env production` 會部署到沒有承接流量的 Worker。
6. **回滾方式**：KV 原資料不刪，出問題就 `git revert` 後重新部署，立刻回到 KV 版本。確認穩定數週後再清 KV 舊資料。
7. **住宿生點名控管／學號查詢／開課報表**（`boarding-attendance.ts`、`course-report.ts`）改成 SQL 查詢。

### 後續階段（視需要）

- 第二階段：班級、排課例外搬 D1，順便修漏洞 #10、#11、#12。
- 第三階段：optional-course 可維持 KV（設計已健全），不一定要搬。
- 登入改 Google 帳號驗證（漏洞 #2），與 D1 無關，可獨立進行。

3. **部署 Worker**（⚠️ 不要加 `--env production`，那會部署到沒有承接流量的 Worker）
   ```
   npx wrangler deploy
   ```
   optional-course 也要部署一次（在 `D:\chhsban\optional-course\worker` 執行同一行）。
   兩個 Worker 都用到 `packages/kv-utils`，部署前先在 `packages/kv-utils` 執行 `npx tsc`（會有一個既有的型別錯誤，但仍會產生 dist，可忽略）。
4. **驗證**
   - tution-portal 用老師帳號：首頁課程列表、名單頁、點名頁（看得到舊點名）、排課頁
   - admin-portal：補習班已開課管理、住宿生點名控管、學號查詢、各課程開課報表
   - 報表是快照，部署後第一次要用 super_admin 在後端 `POST /api/v1/reports/course-summary/refresh` 或等隔天 cron
5. **刪除不再使用的 secret**
   ```
   npx wrangler secret delete GOOGLE_SHEETS_API_KEY
   npx wrangler secret delete GOOGLE_SERVICE_ACCOUNT_EMAIL
   npx wrangler secret delete GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY
   npx wrangler secret delete GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY_ID
   ```
