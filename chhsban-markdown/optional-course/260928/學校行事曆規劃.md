# optional-course 學校行事曆 規劃

日期：2026-09-28
專案位置：`D:\chhsban\optional-course`

## 背景

選修課與 tution 補習班的排課方式不同：選修課跟著學校時間表統一排課，
**只要當天學校有上課、且是該課的上課星期，就一定要點名**。

目前系統沿用 tution 的做法——以課程的 `day_of_week` + `start_date/end_date` 推算上課日，
`OptionalCourseSchedule` 只存單門課的停課／調課；點名頁可自由選日期，系統並不知道
「哪一天必須點名」，也無法追蹤漏點名。

因此在管理員端新增「學校行事曆」，排定全校上課日與假期，由它推算每門課的應點名日期。

## 已確認的前提

1. 課表為**固定每週循環**（非 Day 1–6 輪轉制），星期日一律休息。
2. 一門選修課**每週只上一次**，`day_of_week` 維持單一值。
3. 課程級停課／調課過去兩年未發生過；若真的有，**只有管理員可以登記**，老師不能自行登記。
4. 週六：預設休息；若有週六上課（補課、校慶等），一律登記為「補課日」處理，資料結構不需另外設計。

## 核心概念：三層疊加

```
學校行事曆（全校共用，管理員維護）   → 哪天學校上課、按星期幾的課表上
× 課程每週時段（course.day_of_week） → 這門課在哪些上課日有課
− 課程級例外（OptionalCourseSchedule，僅管理員）
= 這門課的「應點名日期」清單
```

## 資料設計

### KV

放進現有的 `OPTIONAL_COURSE_SCHEDULE_KV`，不另開 namespace：

| key | 內容 |
|---|---|
| `calendar:{year}` | 該年度的 `SchoolCalendar`（單一 JSON） |

年度以**日曆年**為單位，與課程依年份管理的設計一致（`year.ts`）。
每日排程的過期清理一併刪除 `RETAINED_YEARS` 之前的 `calendar:{year}`。

### 型別（`worker/src/types.ts`，前端 `types/index.ts` 同步）

```ts
type Weekday = "Monday" | "Tuesday" | "Wednesday" | "Thursday" | "Friday" | "Saturday";

interface SchoolHoliday {
  holiday_id: string;           // holiday_<ts>_<rand>
  start_date: string;           // YYYY-MM-DD
  end_date: string;             // YYYY-MM-DD（單日假期 start = end）
  name: string;                 // 「開齋節」「年中假期」
  type: "public" | "school_break" | "event"; // 國定假日／學校假期／校內活動停課
}

interface SchoolMakeupDay {
  date: string;                 // YYYY-MM-DD
  follows_weekday: Weekday;     // 當天按星期幾的課表上課
  note?: string;
}

interface SchoolCalendar {
  year: number;
  term_start?: string;          // 開學日；未設定前整年視為「行事曆未建立」
  term_end?: string;            // 結業日
  holidays: SchoolHoliday[];
  makeup_days: SchoolMakeupDay[];
  updated_at: number;
  updated_by: string;           // teacher_id
}
```

只存「規則＋例外」，不存每一天的狀態：長假一筆區間即可，資料量小、好維護。

### 判定規則（`worker/src/calendar.ts`，純函式，前後端共用同一套邏輯）

`resolveDay(calendar, date) → { is_school_day, follows_weekday?, reason }`，依序：

1. 不在 `term_start`～`term_end` 之間 → 休
2. 是補課日 → 上課，按 `follows_weekday`
3. 落在任一假期區間內 → 休（reason = 假期名稱）
4. 星期日 → 休；星期六 → 休
5. 其他 → 上課，按當天星期幾

`listCourseSessions(calendar, course, schedules) → string[]`：
行事曆中 `follows_weekday === course.day_of_week` 的上課日，
扣掉課程級停課、加上課程級調課的目的日期。

日期計算一律以馬來西亞時間（UTC+8）判定，比照 `year.ts`。
（順帶修正：`AttendanceSheet` 預設日期目前用 `toISOString()`，是 UTC，早上 8 點前會取到前一天。）

## API

| 方法 | 路徑 | 權限 | 說明 |
|---|---|---|---|
| GET | `/api/v1/calendar?year=` | 登入者 | 取得行事曆（未建立回傳空結構） |
| PUT | `/api/v1/calendar/{year}` | admin | 整份覆寫；帶 `updated_at` 做樂觀鎖，不符回 409 |
| PUT | `/api/v1/courses/{id}` | admin | 設定上課星期／時間／地點（原本前端沒有地方設定上課星期） |
| GET | `/api/v1/courses/{id}/sessions` | 課程老師或 admin | 該課應點名日期＋各日是否已點名／漏點名 |
| GET | `/api/v1/attendance/summary?year=` | admin | 每門課已點名／應點名堂數＋漏點名日期 |
| POST | `/api/v1/courses/{id}/schedules` | **改為僅 admin** | 課程級停課／調課（原訂日期須為該課上課日） |
| DELETE | `/api/v1/courses/{id}/schedules/{sid}` | admin | 取消停課／調課登記 |

Excel 匯入在前端解析，合併進編輯中的行事曆，再透過 PUT 一起儲存，不另設匯入端點。
行事曆只能編輯今年、明年；往年唯讀。

**影響檢查**：PUT 行事曆時，若新增的假期（或移除的補課日、縮短的學期）蓋到已有點名紀錄的日期，
回 409 並列出受影響的課程與日期；前端顯示警告，管理員確認後帶 `force: true` 再送出。
檢查方式：當年每門課 list 一次 `attendance:{course_id}:` prefix，比對日期。

**點名驗證**：POST 點名時，worker 檢查 `class_date` 必須在該課應點名日期內，否則回 `NOT_A_SESSION_DATE`。
行事曆尚未建立（無 `term_start`）時不擋，避免上線初期卡住老師。

## 前端

### 管理員：行事曆頁 `/admin/calendar`（新）

- 年份切換（今年／明年），設定開學日、結業日
- **全年總覽**：12 個小月曆，顏色區分上課日／國定假日／學校假期／活動停課／補課日／週末
- 點選或拖選日期 → 新增假期或補課日；右側清單可編輯、刪除
- **Excel 批量匯入**：比照 `RosterBatchImport`，附範本檔（名稱、類型、起日、迄日）。
  國定假日各州不同、伊斯蘭節日每年浮動，不接外部 API，每年初由行政一次匯入
- 顯示統計「本年上課日共 N 天、週一～週五各 N 天」，方便與學校官方行事曆核對
- 儲存時的影響檢查警告（見上）

### 管理員：未點名追蹤

- `AdminCourseList` 每門課顯示「已點名 / 應點名」堂數，未點名數以紅字標示
- 新增 `/admin/attendance/missing`：依日期列出未點名的課程與老師

### 管理員：課程停課／調課

- 現有 `ScheduleManagement` 搬到 `/admin/courses/:id/schedule`，只有 admin 可進
- 老師端 `/courses/:id/schedule` 改為唯讀「上課日期表」（顯示所有應點名日期及點名狀態）

### 路由權限

`App.tsx` 的 `RESTRICTED_ALLOWED_PATHS.admin` 目前只允許 `/admin/courses`，
改為允許 `/admin/` 開頭的所有路徑（比對方式由 `includes` 改為 prefix 比對）。

### 老師端

- **點名頁**：日期改為下拉選單，只列應點名日期（預設今天，今天無課則預設最近一次未點名的課）；
  已點名的日期標示 ✓，可重新點名修改
- **TeacherDashboard**：每門課顯示「你有 N 堂未點名」

### 課程起訖日

`start_date/end_date` 預設等於學期起訖（未設定時即以行事曆的 `term_start/term_end` 計算），
只有中途開課的特殊情況才需要覆蓋。

## 實作結果（2026-09-29）

已依上述設計完成，與原規劃的差異：

- 原本建課只填名稱、前端沒有設定上課星期的地方 → 課程總覽新增「上課星期」下拉（建課時可選，之後可改）
- 「未點名清單」做成 `/admin/attendance`「點名追蹤」頁，可切換依課程／依日期檢視
- 漏點名只計算「課程窗口開放後、今天以前（已關閉的課則到關閉日為止）」的上課日
- 點名頁只列今天以前的上課日；已點過名的日期會帶出原本的紀錄，可修改後更新
- 行政人員頁首新增導覽：課程總覽／學校行事曆／點名追蹤
- Excel 範本：`optional-course/frontend/public/calendar-template.xlsx`

驗證：worker、前端 `tsc --noEmit` 皆通過；`calendar.ts` 判定邏輯以腳本斷言測試；
本機 `wrangler dev` 走過完整情境（建課→行事曆未建立時自由點名→建立行事曆觸發影響檢查→force 儲存→
樂觀鎖衝突→非上課日點名被擋→admin 停課／取消→老師登記停課被擋）。

## 實作順序

1. 型別＋`calendar.ts` 判定函式（先寫好，後面全部依賴它）
2. 行事曆 API（GET/PUT＋樂觀鎖＋影響檢查）、過期清理納入 `calendar:{year}`
3. 管理員行事曆頁（全年總覽、編輯、匯入）
4. `sessions` API＋點名頁日期下拉＋點名驗證
5. 未點名追蹤（admin 清單、課程列表統計、老師 dashboard 提示）
6. 課程停課／調課改為 admin 專屬、老師端改唯讀
7. `tsc --noEmit` 前後端通過 → commit＋push（由 GitHub Actions 部署）
