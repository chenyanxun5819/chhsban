# optional-course（選修課點名系統）建置報告

日期：2026-09-09
專案位置：`D:\chhsban\optional-course`

## 背景

新開一個「選修課點名」網頁專案，學生/老師來源與既有的 `chhsban-tution` + `tution-portal`
補習班系統完全相同，差異只在於：不收費、不需要老師個人的申請書，且角色分工不同——
行政人員只負責開課程窗口＋綁定授課老師（監管角色），授課老師綁定後自行管理名冊、排課、點名。

## 討論階段：兩個前提問題

1. **是否該把這些專案集合在同一個工作區？** → 合適。D:\chhsban 本來就是單一 git repo +
   npm workspaces 的 monorepo，`chhsban.code-workspace` 也已預先列了一個空的
   `optional-course` 項目，所以 optional-course 直接作為兄弟資料夾放入即可，不會造成混亂。
2. **學生/老師來源是否與 tution 系統相同？** → 是，但實作上發現學生/老師資料並非放在共用
   套件裡，而是完全歸 `chhsban-tution` 的 Worker 自己管（Cloudflare KV：`STUDENT_KV`、
   `TEACHER_KV`、`AUTH_KV`、`CLASSROOM_KV`）。因此決定讓 optional-course 的新 Worker
   直接綁定「同一組」KV namespace id 來讀取，而不是重建一套帳號系統。

進一步確認角色分工後，最終架構決定：

- 獨立新 Worker（`optional-course-system`）＋獨立新前端（Cloudflare Pages），與
  `chhsban-tution`/`tution-portal` 完全解耦部署，只共用資料層。
- 目錄放在 `D:\chhsban\optional-course\worker` 與 `D:\chhsban\optional-course\frontend`
  兩個子資料夾下（而非另開頂層資料夾），因為 `chhsban.code-workspace` 已經只登記了一個
  `optional-course` 項目。

完整規劃記錄於 Claude Code 的 plan 檔：
`C:\Users\MSI\.claude\plans\d-chhsban-optional-course-d-chhsban-chh-wiggly-snowglobe.md`。

## 已完成的工作

### 後端（`optional-course/worker/`）

- `wrangler.toml`：綁定與 `chhsban-tution` 完全相同的 4 個共用 KV id
  （`STUDENT_KV`/`TEACHER_KV`/`AUTH_KV`/`CLASSROOM_KV`），另外規劃了 4 個
  optional-course 專屬 KV（`OPTIONAL_COURSE_KV`／`_ROSTER_KV`／`_SCHEDULE_KV`／
  `_ATTENDANCE_KV`，目前為佔位 id，尚未實際建立，見下方「尚未完成」）。
  刻意不加 `[env.production]`，避免重演 `chhsban-tution` 那次 `--env production`
  部署到未生效 Worker 的問題（`worker/README.md` 有詳細說明）。
- `src/types.ts`：選修課的本地型別（`OptionalCourse`/`OptionalCourseRoster`/
  `OptionalCourseSchedule`/`OptionalCourseAttendance`），對照 tution 系統的
  `TutionClass` 系列拿掉收費欄位，`approval_status` 改為 `window_status`
  （pending/open/closed，對應「未綁老師／已開放／已關閉」）。
- `src/optional-course-service.ts`：KV CRUD 邏輯，結構比照
  `chhsban-tution/src/tution-service.ts` 的 `TutionKVService`。
- `src/index.ts`：
  - `/api/auth/*` 系列直接照抄 `chhsban-tution` 的登入邏輯（純操作共用的
    `TEACHER_KV`/`AUTH_KV`，完全不用改）。
  - Admin 專屬：建課、綁定老師、開／關窗口、唯讀監管端點。
  - 授課老師專屬（限本人綁定的課程，或 admin 可覆蓋）：名冊加退、排課、點名 CRUD。
- 已安裝依賴、跑過 `tsc --noEmit`（0 錯誤，另外補了 `@cloudflare/workers-types`，
  這點連 `chhsban-tution` 自己都沒設，算是順手補上的小改善）。
- 用 `wrangler dev` 在本機啟動過，`/api/health` 及未帶 token 的請求都回應正確
  （401/404 符合預期）。因為本機是模擬的空 KV，還沒有拿真實老師帳號測過完整登入流程。

### 前端（`optional-course/frontend/`）

- Vite + React + TypeScript，結構比照 `tution-portal`：`utils/api.ts`、
  `services/authService.ts`、`context/AuthContext.tsx` 幾乎逐字複製（通用登入邏輯）。
- 頁面：`Login`（兩階段密碼登入，拿掉了 tution-portal 的 Google OAuth 選項，只留手動
  Email 登入）、`AdminCourseList`（建課/選老師綁定/開關窗口）、`TeacherDashboard`
  （我的課程列表）、`RosterManagement`（查學生+加入/退出名冊）、`ScheduleManagement`
  （登記停課/調課）、`AttendanceSheet`（逐堂點名）。
- 路由依兩角色簡化：admin 只能進 `/admin/courses`，老師可以進
  `/my/courses`、`/courses/:id/roster`、`/courses/:id/schedule`、`/courses/:id/attendance`。
- `tsc --noEmit` 0 錯誤，`npm run build` 成功產出 `dist/`。
- 本地開發埠號設定為 5174（`tution-portal` 用 5173，避免衝突）。

## 尚未完成（下一步）

1. **建立真正的 KV namespace**：`wrangler.toml` 裡 4 個 `OPTIONAL_COURSE_*_KV` 目前是
   `REPLACE_WITH_REAL_KV_ID` 佔位字串，需要登入 Cloudflare 帳號執行
   `wrangler kv:namespace create OPTIONAL_COURSE_KV`（其餘 3 個同理）後填入。
2. **設定 Worker 密鑰**：`wrangler secret put AUTH_PENDING_SECRET`（用來簽署登入流程的
   pending token，只在本 Worker 內部使用，跟 chhsban-tution 的可以不同）。
3. **首次部署**：`npm run deploy`（即不帶 `--env` 的 `wrangler deploy`），拿到實際的
   `*.workers.dev` 網址後，回填前端的 `VITE_API_BASE_URL`。
4. **新增前端部署的 GitHub Actions workflow**：`.github/workflows/deploy-optional-course.yml`
   （比照現有的 `deploy-tution-portal.yml`），目前還沒建立這個檔案。
5. **拿真實帳號做端到端驗證**：admin 建課 → 綁老師 → 開窗 → 老師登入管理名冊
   （用真實 `STUDENT_KV` 學生）→ 排課 → 點名 → admin 唯讀監管畫面確認資料，以及確認
   403 情境（admin 打名冊/點名端點應被拒、非綁定老師打該課程端點應被拒）。
6.（低優先）在 `packages/cloudflare-config/src/kv-namespace.ts`／`workers.ts` 補登記
   新 Worker 與新 KV，純作盤點文件用途。
