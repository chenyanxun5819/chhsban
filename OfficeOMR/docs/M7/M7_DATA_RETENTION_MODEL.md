**答**：❌ 错误理解 → ✅ 正确理解

|------|-----------------|-------------------|------|
| 标准答案 | 24小时删除 | **永久保存** | 老师改卷超24h；隔年复用试卷 |

## 🎯 两类数据的分类

### 第一类：教题目层面（永久保存）
这些是题目本身的资料，不含学生信息。

| 数据 | 存储位置 | 保留期 | 为什么 |
|------|---------|--------|---------|
| **标准答案** | `jobs/{jobId}.answerKey` | **永久** | 评分用 + 隔年复用 |
| **题目文件** | `papers/{orgId}/{teacherId}/*.pdf` | **永久** | 试卷本身 |
| **考试元数据** | `jobs/{jobId}.{examName, subject, grade}` | **永久** | 考试信息 |

**特点**:
- ✅ 不含学生学号、姓名
- ✅ 不含学生答案
- ✅ 可以跨年份复用
- ✅ 教师需要长期保留以供参考

### 第二类：学生层面（24小时删除）
这些是学生的个人数据，包含隐私信息。

| 数据 | 存储位置 | 保留期 | 为什么 |
|------|---------|--------|---------|
| **答案卡原图** | `uploads/{jobId}/*` | **24小时** | 含学号、姓名 |
| **标注 PDF** | `annotated/{jobId}/*` | **24小时** | 学生批改结果（含名字） |
| **识别结果** | `jobs/{jobId}.result.sheets[*]` | **24小时** | 学生答案 + 分数 |
| **分析数据** | `jobs/{jobId}.result.*` | **24小时** | 学生成绩分析 |

**特点**:
- ❌ 包含学号、姓名等PII（personally identifiable information）
- ❌ 包含学生答案和分数
- ❌ 隐私敏感，不能长期保留
- ✅ 教师可在24小时内下载查看

## 🔐 隐私与合规

### 为什么学生数据要 24 小时删除？

**学生隐私法规**:
- 学号、姓名 → **PII（个人可识别信息）**
- 考试成绩 → **教育隐私**
- 答案卡图片 → **生物识别数据**（手写字迹）

**数据保留原则**:
- 只保留**必要的数据**，只保留**必要的时间**
- 学生数据不能长期保留在系统中
- 教师有责任在 24 小时内下载和备份

### 为什么标准答案可以永久保存？

**标准答案不是个人数据**:
- ✅ 只有答案（A/B/C/D/E），没有学生信息
- ✅ 不能识别任何学生
- ✅ 属于**题目资料**，不属于**学生资料**
- ✅ 教师需要长期保留以供参考和复用

**类比**：
- ❌ 教科书 + 学生笔记 → 24小时删笔记，永久保留教科书
- ❌ 答案卡 + 标准答案 → 24小时删答案卡，永久保留标准答案

## ⚙️ 技术实现

### 24小时删除的触发机制

**选项1: TTL + Lifecycle Rules（推荐）**
```
Firestore:
  - 每个 job 文档有 expiresAt 字段
  - 24小时后自动删除（使用 Firebase TTL 功能）

Cloud Storage:
  - 为 uploads/ 和 annotated/ 前缀配置生命周期规则
  - 24小时后自动删除
  - 严格不允许删除 papers/ 前缀
```

**选项2: Cloud Scheduler + Cloud Function**
```
每小时执行一次:
  SELECT jobs WHERE expiresAt <= NOW()
  FOR EACH job:
    1. 删除 uploads/{jobId}/* 
    2. 删除 annotated/{jobId}/*
    3. 清空 jobs/{jobId}.result
    4. 验证 jobs/{jobId}.answerKey 未被删
```

### 防删保护

```javascript
// Firestore Security Rules
match /jobs/{jobId} {
  // 禁止删除 answerKey 字段
  allow update: if !("answerKey" in request.resource.data.diff(resource.data).affectedKeys());
  
  // 允许删除 result 字段（清理函数用）
  allow update: if request.auth.token.firebase.sign_in_provider == "custom";
}
```

## 🎓 业务场景

### 场景 1：24小时内改卷

**流程**:
```
14:00  上传学卷 → 识别 → 生成标注 PDF
  ↓
15:00  老师查看结果
  ↓
22:00  老师改卷完毕，下载 CSV + 标注 PDF 打印给学生
  ↓
✅ 成功（还有 16 小时可以下载）
```

**结果**:
- ✅ 学生能及时拿到批改结果
- ✅ 学生数据安全删除
- ✅ 标准答案永久保留

---

### 场景 2：改卷超过 24小时

**流程**:
```
14:00  上传学卷 → 识别 → 生成标注 PDF
  ↓
   ... 老师开会、改卷、其他事情 ...
  ↓
明天 15:00  老师才想起来要改卷 ← 已过期！
  ↓
❌ 学卷已删除，不能再查看
```

**解决**:
- 老师应该在 24小时内下载备份
- 或者系统提醒：还剩 2 小时，尽快下载
- 但**标准答案永久保存**，不用重新上传

---

### 场景 3：隔年复用试卷

**流程**:
```
2026-11-11  第一次考试
  ├─ 上传标准答案 ✅
  ├─ 学生答卷识别 + 批改
  ├─ 学生数据 24h 后删除
  └─ 标准答案永久保存

2027-11-11  隔年复用（第二年）
  ├─ 选择去年的试卷 → 复制
  ├─ 标准答案自动带过来 ✅ 不用重新上传
  ├─ 打印新的答案纸给学生
  ├─ 学生答卷识别 + 批改
  └─ 新的学生数据 24h 后删除
```

**优势**:
- ✅ 标准答案永久保留，节省时间
- ✅ 每个年份的学生数据独立删除，隐私安全
- ✅ 试卷可重复使用，资源高效

## 🚀 迁移到试卷库（第二阶段）

当项目升级到试卷库（`exams/{examId}`）时：

```
不变:
  ✅ 标准答案永久保存（从 jobs/ 迁到 exams/）
  ✅ 学生数据 24小时删除

变化:
  jobs/{jobId} → 只保存一次考试的数据
  exams/{examId} → 保存可复用的试卷及标准答案
```

**迁移前**: M7 答案存在 `jobs/{jobId}.answerKey`  
**迁移后**: 答案存在 `exams/{examId}.answerKey`，jobs 引用它
