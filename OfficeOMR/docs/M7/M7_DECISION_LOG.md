### 事件 2️⃣ 保留期理解错误

**时间**: 2026-11-11 中午  
**人物**: Wes（业务）+ Copilot（发现错误）  
**问题**:
> 标准答案为什么要 24 小时删除？如果老师改卷没在 24 小时完成，是不是还要重新上传一遍标准答案？

**发现**:
- ❌ Copilot 的初版设计让标准答案也 24 小时删除（错误）
- ✅ Wes 指正：标准答案应该永久保存

**影响**:
- ❌ 影响教师体验（改卷超 24h 还要重新上传）
- ❌ 影响试卷复用（隔年用不了标准答案）
- 严重程度：**重大设计缺陷**

**最终决策**:
| 项目 | ❌ 错（初版） | ✅ 对（修正） |
|------|-----------|------------|
| 标准答案 | 24h 删除 | **永久保存** |
| 学生数据 | 不明确 | **24h 删除** |
| 题目文件 | 不明确 | **永久保存** |

**改正依据**:
1. 标准答案不含隐私信息（只有答案 A/B/C/D/E）
2. 老师改卷可能超过 24 小时
3. 标准答案要伴随试卷永久保留，供隔年复用
4. 只有**学生数据**（含学号、答案）才需要 24 小时删除

### 事件 3️⃣ 数据分类厘清

**时间**: 2026-11-11 下午  
**人物**: Wes + Copilot  
**背景**:
上一个事件暴露了数据分类混乱的问题。需要明确：
- 哪些是"题目层面"（永久保存）
- 哪些是"学生层面"（24小时删除）

**最终分类**:

**题目层面（永久）**:
```
✅ 标准答案              ← 题目资料，无隐私
✅ 题目文件 (PDF)        ← 试卷本身
✅ 考试元数据            ← 科目、年级、名称
```

**学生层面（24小时）**:
```
❌ 答案卡原图            ← 含学号、姓名
❌ 标注 PDF              ← 学生的批改结果（含名字）
❌ 识别结果              ← 学生的答案数据
❌ 分析数据              ← 学生的成绩
```

**实施影响**:
- ✅ 清理函数必须严格区分两类数据
- ✅ Storage 生命周期规则必须按前缀隔离
- ✅ Firestore 删除逻辑必须保护 `answerKey`
- ✅ 需要添加单元测试验证

**添加**:
```
【关键原则】数据分为两类：
1. 题目层面（永久保存）
   - 标准答案：jobs/{jobId}.answerKey
   - 题目文件：papers/{orgId}/{uid}/*.pdf
   
2. 学生层面（24小时删除）
```

## 🎯 核心设计决策

### 决策 1: 两种标准答案获取方式

**选项**:
```
方案A：扫描标准答案卡
  - 老师打印空白卡，涂出答案
  - 系统用 OMR 识别
  - 优点：快速、自动、重用已有代码
  
方案B：手动输入
  - 网页表单逐题选择
  - 或粘贴 JSON/CSV
  - 优点：灵活、备选方案
```

**最终决策**: **都支持**（待 Wes 确认）

**理由**:
- 方案A 快速但可能有识别失败
- 方案B 慢但可靠
- 两个都有才最灵活

**代码影响**:
- 需要实现 `AnswerKeyManager.upload_answer_key_by_scan()`
- 需要实现 `AnswerKeyManager.upload_answer_key_by_manual()`

---

### 决策 2: 标准答案保留期

**选项**:
```
❌ 方案A：24小时删除（初版错误的选择）
  - 问题：老师改卷超24h时没有标准答案
  - 问题：隔年复用试卷时要重新上传
  
✅ 方案B：永久保存（Wes 的正确指正）
  - 优点：教师友好、试卷可复用
  - 优点：标准答案不含隐私信息
```

**最终决策**: **方案B - 永久保存**（已确认）

**理由**:
1. 隐私考量：标准答案只有答案，无 PII（personally identifiable information）
2. 功能考量：老师改卷需要时间，可能超 24 小时
3. 业务考量：同一份试卷要隔年复用，标准答案不能丢
4. 对标准答案的定义：它是**题目资料**，不是**学生资料**

**代码影响**:
- 清理函数不能删除 `jobs/{jobId}.answerKey`
- Storage 生命周期规则不能删除 `papers/` 前缀
- Firestore rules 必须保护 `answerKey` 字段
- 需要单元测试验证

---

### 决策 3: 学生数据 24小时删除范围

**删除范围**:
```
✅ 必须删除（含隐私）：
  - uploads/{jobId}/*           上传的答案卡原图
  - annotated/{jobId}/*         标注 PDF（含学生名字）
  - jobs/{jobId}.result.sheets  学生答案数据
  
❌ 不能删除（无隐私）：
  - jobs/{jobId}.answerKey      标准答案
  - papers/{orgId}/{uid}/*      题目文件
  - jobs/{jobId}.{examName,...} 考试元数据
```

**最终决策**: 如上（已确认）

**代码影响**:
- Storage 生命周期规则必须精确配置
- 清理函数循环删除时必须检查前缀
- Firestore 删除时必须用 DELETE_FIELD，不能删整个文档

---

### 决策 4: 答案冻结机制

**选项**:
```
❌ 方案A：不冻结
  - 问题：老师可以事后改标准答案，造成不公平
  
✅ 方案B：第一个学生提交后冻结
  - 优点：防止事后改答案
  - 优点：保证评分的公平性
```

**最终决策**: **方案B - 冻结**（待 Wes 确认）

**实现**:
```
触发时机：第一张学卷上传 + 识别完成后
操作：设置 jobs/{jobId}.answerKey.frozen = true
结果：之后不能修改 answerKey（但仍可添加新学卷）
如果要改答案：只能删除这个考试，重新创建
```

---

### 决策 5: 分数计算标准

**假设公式**:
```
分数 = (答对题数 / 100) × 4.0

例如：
  87 答对 → 87/100 × 4.0 = 3.48 分
  92 答对 → 92/100 × 4.0 = 3.68 分
```

**最终决策**: 待 Wes 确认

**依据**:
- 大马教育制度（Borang IAGM600FC）使用 0-4.0 分制
- 100 题答卷，满分 4.0 分
- 建议保存 `jobs.maxScore` 字段，允许不同考试不同满分

---

### 决策 6: 班级分析报表时机

**选项**:
```
方案A：M7 就做班级分析
  - 优点：完整功能
  - 缺点：代码复杂，数据库结构不优
  
方案B：班级分析留到第二阶段
  - 优点：M7 简单专注
  - 缺点：等久一点
```

**最终决策**: 待 Wes 确认（倾向方案B）

**理由**:
- M7 专注于单个考试、单个学生的识别和批改
- 班级分析需要聚合多个考试数据，代码逻辑不同
- 第二阶段可以优化数据结构，专门为报表设计
